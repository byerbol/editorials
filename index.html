    Условие

    Дан массив $a_1, \dots, a_n$ и $q$ запросов двух типов: 1 i j — присвоить $a_i = j$; 2 l u — вывести XOR значений XOR всех подотрезков отрезка $[l, u]$.

    n, q ≤ 2·10⁵0 ≤ aᵢ ≤ 10⁹

    Ключевая идея

    Элемент $a_i$ входит ровно в $(i-l+1)(u-i+1)$ подотрезков отрезка $[l, u]$. В XOR он остаётся, только если это число нечётно.

    Отсюда ответ: при чётной длине $u-l+1$ он равен $0$, при нечётной — $a_l \oplus a_{l+2} \oplus \dots \oplus a_u$.

    Подзадачи

    Подзадача 112 б.n, q ≤ 100

    Перебор по определению: для каждого запроса перебираем пары $l \le x \le y \le u$, XOR подотрезка наращиваем при сдвиге $y$.

    O(q·n²)
    Подзадача 218 б.n, q ≤ 500, без изменений

    Тот же перебор, около $1.25 \cdot 10^8$ простых операций. Можно взять префиксные XOR: XOR подотрезка $[x, y]$ равен $p_y \oplus p_{x-1}$.

    O(q·n²)
    Подзадача 325 б.n, q ≤ 5000

    Используем наблюдение про чётность: для каждого $i \in [l, u]$ проверяем, нечётно ли $(i-l+1)(u-i+1)$. Изменение — просто присваивание.

    O(q·n)
    Подзадача 420 б.без изменений

    Префиксный XOR с шагом 2: $px_i = px_{i-2} \oplus a_i$. При нечётной длине ответ $px_u \oplus px_{l-2}$.

    $px_u$ — XOR позиций той же чётности, что $u$. При нечётной длине $l$ и $u$ одной чётности, и разность оставляет ровно $l, l+2, \dots, u$.
    O(n + q)
    Подзадача 525 б.без ограничений

    Два дерева Фенвика с операцией $\oplus$: одно для чётных позиций, другое для нечётных. Изменение $a_i$ — «добавить» $a_i^{old} \oplus a_i^{new}$ в дерево нужной чётности. Запрос — XOR двух префиксов в дереве той же чётности, что $l$.

    У $\oplus$ каждый элемент сам себе обратный: XOR на отрезке равен $\mathrm{pref}(r) \oplus \mathrm{pref}(l-1)$, а замена $a$ на $b$ — это добавление $a \oplus b$.
    O((n + q) log n)

    Почему это верно

    Сколько подотрезков содержат $a_i$. Подотрезок $[x, y] \subseteq [l, u]$ содержит $i$, когда $l \le x \le i$ и $i \le y \le u$. Начало выбирается $i-l+1$ способами, конец — $u-i+1$, независимо.

    Важна только чётность. $v \oplus v = 0$, поэтому элемент, вошедший в XOR $c$ раз, даёт $a_i$ при нечётном $c$ и $0$ при чётном.

    Чётная длина. $(i-l+1) + (u-i+1) = L + 1$ нечётно, значит один множитель чётен для каждого $i$. Ответ $0$.

    Нечётная длина. Сумма множителей чётна, значит они одной чётности. Оба нечётны ⇔ $i \equiv l \pmod 2$. ∎

    Решение на C++

    A.cpp · 60 строк
    #include <bits/stdc++.h>

using i64 = long long;

struct Fenwick {
    int n;
    std::vector<int> a;
    
    Fenwick(int n_ = 0) : n(n_), a(n_) {}
    
    void add(int x, int v) {
        for (int i = x + 1; i <= n; i += i & -i) {
            a[i - 1] ^= v;
        }
    }
    
    int sum(int x) {
        int ans = 0;
        for (int i = x; i > 0; i -= i & -i) {
            ans ^= a[i - 1];
        }
        return ans;
    }
};

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    
    int n, q;
    std::cin >> n >> q;
    
    std::vector<int> a(n);
    std::array<Fenwick, 2> fen{Fenwick(n), Fenwick(n)};
    for (int i = 0; i < n; i++) {
        std::cin >> a[i];
        fen[i % 2].add(i, a[i]);
    }
    
    while (q--) {
        int t, x, y;
        std::cin >> t >> x >> y;
        
        if (t == 1) {
            int i = x - 1;
            fen[i % 2].add(i, a[i] ^ y);
            a[i] = y;
        } else {
            int l = x - 1, r = y - 1;
            if ((r - l + 1) % 2 == 0) {
                std::cout << 0 << "\n";
            } else {
                auto &f = fen[l % 2];
                std::cout << (f.sum(r + 1) ^ f.sum(l)) << "\n";
            }
        }
    }
    
    return 0;
}

    Условие

    Даны цитируемости $N$ статей. Найдите h-индекс: наибольшее $H$, такое что есть $H$ статей с цитируемостью не меньше $H$.

    N ≤ 500 000cᵢ ≤ 10⁶

    Ключевая идея

    Отсортируйте по убыванию: $c_1 \ge c_2 \ge \dots \ge c_N$. Ответ — наибольшее $i$, для которого $c_i \ge i$.

    Подзадач нет, баллы даются за пройденные тесты, поэтому ниже два уровня решения.

    Подзадачи

    Частичнонебольшие тесты

    Перебираем $H$ от $N$ вниз и для каждого считаем, сколько статей имеют цитируемость $\ge H$. Первое подходящее $H$ — ответ.

    O(N²)
    ПолноеN ≤ 500 000

    Сортировка и проверка $c_i \ge i$. Без сортировки: значения не больше $10^6$, считаем $cnt_v$ и идём от больших $H$ к меньшим, накапливая число статей с цитируемостью $\ge H$.

    O(N log N) или O(N + max c)

    Почему это верно

    Назовём $H$ допустимым, если есть $H$ статей с цитируемостью $\ge H$. Лемма: $H$ допустимо ⇔ $c_H \ge H$.

    (⇐) Статьи $1, \dots, H$ имеют цитируемость $\ge c_H \ge H$. (⇒) Если есть $H$ статей с цитируемостью $\ge H$, то $H$-я по величине цитируемость не меньше $H$.

    Если $H$ допустимо, то и $H-1$ тоже. Поэтому ответ — наибольшее $i$ с $c_i \ge i$. ∎

    Условие

    Массив $A$ из $N$ чисел и число $K$. Запросы: 1 i₁ … iₖ — циклически сдвинуть влево значения на этих $K$ позициях; 2 l r m — сумма элементов всех подотрезков длины $m$ внутри $[l, r]$ (элемент считается столько раз, во сколько подотрезков входит).

    N, Q ≤ 100 000K ≤ 10

    Ключевая идея

    Элемент на позиции $i \in [l, r]$ входит ровно в $w(i)$ подотрезков длины $m$:

    $$w(i) = \min(i-l+1,\ r-i+1,\ m,\ r-l+2-m).$$

    Вес — «трапеция»: растёт на 1 от левого края, потом постоянен, потом убывает. На каждом куске он линеен, поэтому хватает сумм $\sum a_i$ и $\sum i \cdot a_i$.

    Подзадачи

    Подзадача 136 б.N, Q ≤ 10 000, K = 1

    При $K = 1$ сдвиг ничего не меняет. Для запроса типа 2 проходим $i$ от $l$ до $r$ и прибавляем $a_i \cdot w(i)$.

    O(N·Q)
    Подзадача 256 б.N, Q ≤ 100 000, K = 1

    Префиксы $S_i = \sum_{j \le i} a_j$ и $T_i = \sum_{j \le i} j \cdot a_j$. Пусть $s = \min(m, r-l+2-m)$. Ответ складывается из трёх кусков:

    $$\sum_{i=l}^{l+s-2}(i-l+1)a_i + s\sum_{i=l+s-1}^{r-s+1} a_i + \sum_{i=r-s+2}^{r}(r-i+1)a_i,$$

    а каждый кусок выражается через $S$ и $T$, например:

    $$\sum_{i=x}^{y}(i-l+1)a_i = (T_y - T_{x-1}) - (l-1)(S_y - S_{x-1}).$$

    Все суммы — в long long.

    O(N + Q)
    Подзадача 38 б.2 ≤ K ≤ 10

    Формула та же, но массив меняется. Вместо $S$ и $T$ — два дерева Фенвика: для $a_i$ и для $i \cdot a_i$. Сдвиг — это $K$ точечных изменений.

    O((N + Q·K) log N)

    Почему это верно

    Подотрезок длины $m$ задаётся началом $s$. Он лежит в $[l, r]$ ⇔ $l \le s \le r-m+1$ и содержит $i$ ⇔ $i-m+1 \le s \le i$. Число таких $s$:

    $$w(i) = \min(i,\ r-m+1) - \max(l,\ i-m+1) + 1 = \min(i-l+1,\ m,\ r-l+2-m,\ r-i+1).$$

    На каждом из трёх участков $w$ имеет вид $\alpha i + \beta$, поэтому сумма $\sum w(i) a_i$ сводится к $\sum a_i$ и $\sum i \cdot a_i$ на отрезках. ∎

    Решение на C++

    C.cpp · 98 строк
    #include <bits/stdc++.h>

using i64 = long long;

template <typename T>
struct Fenwick {
    int n;
    std::vector<T> a;
    
    Fenwick(int n_ = 0) {
        init(n_);
    }
    
    void init(int n_) {
        n = n_;
        a.assign(n, T{});
    }
    
    void add(int x, const T &v) {
        for (int i = x + 1; i <= n; i += i & -i) {
            a[i - 1] = a[i - 1] + v;
        }
    }
    
    T sum(int x) {
        T ans{};
        for (int i = x; i > 0; i -= i & -i) {
            ans = ans + a[i - 1];
        }
        return ans;
    }
    
    T rangeSum(int l, int r) {
        return sum(r) - sum(l);
    }
};

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    
    int n, k;
    std::cin >> n >> k;
    
    std::vector<i64> a(n + 1);
    Fenwick<i64> fa(n), fia(n);
    for (int i = 1; i <= n; i++) {
        std::cin >> a[i];
        fa.add(i - 1, a[i]);
        fia.add(i - 1, i * a[i]);
    }
    
    auto S = [&](int x, int y) -> i64 {
        return x > y ? 0 : fa.rangeSum(x - 1, y);
    };
    auto T = [&](int x, int y) -> i64 {
        return x > y ? 0 : fia.rangeSum(x - 1, y);
    };
    
    int q;
    std::cin >> q;
    
    std::vector<int> p(k);
    std::vector<i64> v(k);
    while (q--) {
        int t;
        std::cin >> t;
        
        if (t == 1) {
            for (int j = 0; j < k; j++) {
                std::cin >> p[j];
                v[j] = a[p[j]];
            }
            for (int j = 0; j < k; j++) {
                i64 nv = v[(j + 1) % k];
                i64 d = nv - a[p[j]];
                a[p[j]] = nv;
                fa.add(p[j] - 1, d);
                fia.add(p[j] - 1, p[j] * d);
            }
        } else {
            int l, r, m;
            std::cin >> l >> r >> m;
            
            int len = r - l + 1;
            int s = std::min(m, len - m + 1);
            
            i64 ans = 0;
            ans += T(l, l + s - 2) - 1LL * (l - 1) * S(l, l + s - 2);
            ans += 1LL * s * S(l + s - 1, r - s + 1);
            ans += 1LL * (r + 1) * S(r - s + 2, r) - T(r - s + 2, r);
            
            std::cout << ans << "\n";
        }
    }
    
    return 0;
}

    Условие

    Сетка $R \times C$: «#» — остров, «.» — вода. Подлодка стартовала в неизвестной клетке воды и сделала $M$ ходов по строке из N/E/S/W, где «?» — неизвестное направление. Подлодка всё время в воде. Сколько клеток могут быть её текущим положением?

    R, C ≤ 500M ≤ 5000

    Ключевая идея

    Храним не пути, а множество $P_t$ клеток, где лодка может быть после $t$ сигналов. $P_0$ — вся вода, ответ — $|P_M|$.

    Переход: $p \in P_t$ ⇔ $p$ — вода и $p - \delta \in P_{t-1}$ для направления $\delta$, разрешённого $t$-м сигналом. Здесь $\delta$ — сдвиг на один шаг: N $=(-1,0)$, E $=(0,+1)$, S $=(+1,0)$, W $=(0,-1)$.

    Подзадачи

    Подзадача 129 б.R, C, M ≤ 100, нет «?»

    Путь известен. Перебираем стартовую клетку воды и моделируем $M$ ходов; если лодка ни разу не вышла на остров или за край — отмечаем конечную клетку.

    O(R·C·M) ≈ 10⁶
    Подзадача 237 б.R, C, M ≤ 100

    Массив $can_{r,c}$ — это $P_t$. На каждом шаге клетка достижима, если это вода и в неё можно прийти из достижимой клетки текущим ходом («?» — любым из четырёх).

    O(R·C·M·4) = 4·10⁶
    Подзадача 334 б.R, C ≤ 500, M ≤ 5000

    Тот же переход — $1.25 \cdot 10^9$ операций, слишком медленно. Храним строку как std::bitset<500>. Ход E — сдвиг строки на 1 бит влево (<< 1), W — вправо, N — взять строку ниже, S — строку выше. «?» — OR всех вариантов. После хода — AND с маской воды.

    Это ровно тот же переход для $P_t$, только 64 клетки обрабатываются одной машинной операцией.
    O(R·C·M / 64)

    Почему это верно

    Допустимый путь длины $t$, заканчивающийся в $p$, — это допустимый путь длины $t-1$, заканчивающийся в $p - \delta$, плюс последний шаг $\delta$ в воду.

    (⇒) Если лодка в $p$ после $t$ сигналов, то до последнего шага она была в $p - \delta \in P_{t-1}$. (⇐) Если $p - \delta \in P_{t-1}$ и $p$ — вода, продлеваем путь до $p - \delta$ шагом $\delta$. По индукции $P_t$ — ровно множество возможных клеток. ∎

    Решение на C++

    D.cpp · 55 строк
    #include <bits/stdc++.h>

using i64 = long long;

constexpr int W = 500;

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    
    int r, c, m;
    std::cin >> r >> c >> m;
    
    std::vector<std::bitset<W>> water(r);
    for (int i = 0; i < r; i++) {
        std::string s;
        std::cin >> s;
        for (int j = 0; j < c; j++) {
            water[i][j] = s[j] == '.';
        }
    }
    
    std::string sig;
    std::cin >> sig;
    
    auto cur = water;
    std::vector<std::bitset<W>> nxt(r);
    for (char ch : sig) {
        for (int i = 0; i < r; i++) {
            std::bitset<W> b;
            if (ch == 'E' || ch == '?') {
                b |= cur[i] << 1;
            }
            if (ch == 'W' || ch == '?') {
                b |= cur[i] >> 1;
            }
            if ((ch == 'N' || ch == '?') && i + 1 < r) {
                b |= cur[i + 1];
            }
            if ((ch == 'S' || ch == '?') && i > 0) {
                b |= cur[i - 1];
            }
            nxt[i] = b & water[i];
        }
        std::swap(cur, nxt);
    }
    
    int ans = 0;
    for (int i = 0; i < r; i++) {
        ans += cur[i].count();
    }
    std::cout << ans << "\n";
    
    return 0;
}

    Условие

    $N$ картин, у картины размер $A_i$ и ценность $B_i$. Выберите непустое множество картин, максимизируя $S - (A_{\max} - A_{\min})$, где $S$ — сумма ценностей выбранных.

    N ≤ 500 000Aᵢ ≤ 10¹⁵Bᵢ ≤ 10⁹

    Ключевая идея

    Отсортируем по $A$. Если выбраны картины с минимумом $A_i$ и максимумом $A_j$, выгодно взять все картины между ними: каждая добавляет $B \ge 1$, а штраф не меняется. Значит, ответ — лучший отрезок $[i, j]$ отсортированного массива.

    Подзадачи

    Подзадача 110 б.N ≤ 16

    Перебираем все $2^N - 1$ непустых подмножеств и для каждого считаем $S$, $A_{\max}$ и $A_{\min}$.

    O(2ᴺ·N)
    Подзадача 220 б.N ≤ 300

    Сортируем по $A$ и перебираем пары $i \le j$; сумму $B$ на отрезке считаем циклом.

    O(N³)
    Подзадача 320 б.N ≤ 5000

    Префиксные суммы $P_k = B_1 + \dots + B_k$: значение отрезка $(P_j - P_{i-1}) - (A_j - A_i)$ за O(1).

    O(N²)
    Подзадача 450 б.без ограничений

    Перепишем: значение $= (P_j - A_j) + (A_i - P_{i-1})$. Первая часть зависит только от $j$, вторая — только от $i$. Для каждого $j$ нужен $\max_{i \le j}(A_i - P_{i-1})$ — поддерживаем его на ходу.

    Порядок важен: сначала обновляем максимум новым кандидатом $i = j$ (пока $P$ ещё равно $P_{j-1}$), потом прибавляем $B_j$. Вариант $i = j$ — одна картина, значение $B_j$.
    O(N log N) из-за сортировки

    Почему это верно

    Пусть в оптимальном наборе минимальный размер у картины $i$, максимальный — у $j$ (после сортировки). Любая картина $k$ с $i < k < j$ имеет $A_i \le A_k \le A_j$: если её добавить, $A_{\max} - A_{\min}$ не изменится, а $S$ вырастет на $B_k \ge 1$.

    Значит, существует оптимальный ответ из всех картин отрезка $[i, j]$, и перебирать нужно только отрезки. ∎

    Решение на C++

    #include <bits/stdc++.h>
using i64 = long long;
int main() {
    int n;
    std::cin >> n;
    std::vector<std::pair<i64, i64>> p(n);
    for (auto &[a, b] : p) std::cin >> a >> b;
    std::sort(p.begin(), p.end());
    i64 P = 0, best = LLONG_MIN, ans = LLONG_MIN;
    for (auto [a, b] : p) {
        best = std::max(best, a - P);
        P += b;
        ans = std::max(ans, P - a + best);
    }
    std::cout << ans << "\n";
}

    Условие

    $N$ учеников в ряд, у $i$-го результат $A_i$. Любой отрезок из двух и более соседей может «списать»: всем на нём ставится максимум отрезка. Это можно делать сколько угодно раз. Ученику $i$ нужно ровно $B_i$. Найдите максимальное число учеников, которые могут сдать одновременно.

    2 ≤ N ≤ 10⁵Aᵢ, Bᵢ ≤ 10⁹1 с

    Ключевая идея

    Ученик $i$ может получить $B_i$ из «источника» $j$, если $A_j = B_i$ и максимум $A$ между $i$ и $j$ равен $B_i$ (нет «стены» с большим числом).

    Несколько учеников сдают одновременно ⇔ их источники можно выбрать неубывающими слева направо: стрелки «ученик ← источник» не пересекаются.

    Подзадачи

    Подзадача 114 б.N ≤ 10

    Перебираем маску сдавших. Проверка: слева направо даём каждому самый левый допустимый источник, не левее предыдущего.

    Жадность верна: более левый источник только ослабляет ограничение для следующих учеников (им нужен источник не левее).
    O(2ᴺ·N²)
    Подзадача 212 б.все Bᵢ = x

    Числа $A_i > x$ — стены. Они режут ряд на куски. Если в куске есть $x$, максимум куска равен $x$, и весь кусок сдаёт сразу. Ответ — суммарная длина кусков, содержащих $x$.

    O(N)
    Подзадача 313 б.N ≤ 5000, A строго возрастает

    Источник может быть только справа (или сам ученик), и он единственный — позиция с $A_j = B_i$. Дальше — длиннейшая неубывающая подпоследовательность источников.

    O(N²)
    Подзадача 423 б.N ≤ 10⁵, все Aᵢ различны

    Источник единственный. Проверяем максимум на отрезке через sparse table, затем длиннейшая неубывающая подпоследовательность источников через бинарный поиск.

    O(N log N)
    Подзадача 516 б.N ≤ 200

    Динамика из подзадачи 6, но $ok(i, j)$ проверяем прямым циклом по отрезку.

    O(N³)
    Подзадача 622 б.N ≤ 5000

    Сетка «ученик $i$ × источник $j$»: галочка, если $ok(i, j)$. Нужно выбрать больше всего галочек так, чтобы в строке была не больше одной, а номер столбца сверху вниз не уменьшался. Это динамика как в LCS:

    $$dp_{i,j} = \max\big(dp_{i,j-1},\ dp_{i-1,j} + ok(i,j)\big).$$

    Переход из $dp_{i-1,j}$ (а не $dp_{i-1,j-1}$), потому что несколько учеников могут брать один источник. Строку $ok(i, \cdot)$ — все $j$ сразу — считаем за $O(N)$: идём от $i$ влево и вправо с текущим максимумом и останавливаемся, когда он превысил $B_i$.

    Для 100 баллов объединяем: при $N \le 5000$ — эта динамика, иначе решение подзадачи 2 или 4.
    O(N²) времени, O(N) памяти

    Почему это верно

    1. Значения не уменьшаются. Списывание ставит максимум отрезка, а он не меньше любого его элемента.

    2. Нужен источник. Новые числа не появляются, значит итоговое $B_i = A_j$ для некоторого $j$, и это значение прошло через все позиции между $i$ и $j$. Если там есть $A_k > B_i$, на позиции $k$ всегда будет больше $B_i$, и любой отрезок через неё имеет максимум больше $B_i$.

    3. Стрелки не пересекаются. Пусть $i < k$, но источник $k$ левее источника $i$. Перебор трёх вариантов расположения показывает, что тогда $B_i = B_k$, и источники можно поменять местами без пересечения. Например, в примере $A = 3\,2\,5\,2\,2\,4$: чтобы ученик 5 получил 5 от ученика 3, пятёрка проходит через ученика 4 и навсегда портит его.

    4. Этого достаточно. Если источники допустимы и не убывают, списываем в порядке возрастания $B$: каждый отрезок «ученик–источник» целиком. Источник к своему ходу ещё хранит своё значение, а более позднее копирование большего числа не задевает уже сдавших. ∎

    Условие

    Строка из $N$ голосов «C» (за Капитана) и «T» (за Тони). Голоса считают дважды: слева направо и справа налево. Капитан доволен, если ни в какой момент подсчёта у него не меньше голосов, чем у Тони. Для $Q$ запросов $[L, R]$ (голосуют только фанаты с $L$ по $R$) найдите минимальное число голосов, которые нужно аннулировать.

    N, Q ≤ 500 000пример: CCCTTTTTTCC → 4, 6, 3

    Ключевая идея

    Положим $T = +1$, $C = -1$. Ответ — лучшая пара непересекающихся префикса и суффикса отрезка (пустые разрешены):

    $$\max_{L-1 \le i \le j \le R}\big(\mathrm{pref}(L..i) + \mathrm{suf}(j{+}1..R)\big).$$

    Для «CCCTTTTTTCC»: пустой префикс плюс суффикс «TTTTTTCC» даёт $6 - 2 = 4$.

    Подзадачи

    Подзадача 128 б.N, Q ≤ 2000

    Жадность: идём слева направо с балансом; если T сделал бы баланс отрицательным — аннулируем его. Затем справа налево по оставшимся голосам — то же самое.

    O(N·Q)
    Подзадача 254 б.N, Q ≤ 70 000

    Для отрезка храним четвёрку $(sum, pre, suf, ans)$, где $pre$ и $suf$ — лучший префикс и суффикс (не меньше 0). Четвёрки склеиваются за O(1) (формулы ниже), поэтому подходит корневая декомпозиция: блоки по $\sqrt N$, запрос собираем из целых блоков и краёв.

    O((N + Q)·√N)
    Подзадача 318 б.N, Q ≤ 500 000

    Дерево отрезков на четвёрках. Лист T: $(1, 1, 1, 1)$, лист C: $(-1, 0, 0, 0)$. Склейка $L$ и $R$:

    $$pre = \max(L.pre,\ L.sum + R.pre),\quad suf = \max(R.suf,\ R.sum + L.suf),$$ $$ans = \max(L.ans + R.sum,\ L.sum + R.ans,\ L.pre + R.suf).$$

    Три случая для $ans$: обе границы в $L$ (суффикс захватывает весь $R$), обе в $R$ (префикс захватывает весь $L$), или префикс из $L$ и суффикс из $R$. Склейка не коммутативна — куски собираем строго слева направо.
    O((N + Q) log N)

    Почему это верно

    Нижняя оценка. Если на префиксе сумма $s > 0$, голосов T там на $s$ больше, и аннулировать нужно хотя бы $s$ голосов T внутри этого префикса. Так же для суффикса. Непересекающиеся префикс и суффикс требуют разных удалений, поэтому нужно не меньше $\mathrm{pref}(i) + \mathrm{suf}(j+1)$.

    Жадность достигает оценки. Пусть правый проход последний раз удалил голос на позиции $y$. На суффиксе $[y, R]$ после всех удалений баланс ровно 0, значит там удалено $\mathrm{suf}(y)$ голосов. Левее $y$ левый проход удалил ровно максимум префикса до $y$. Итого жадность удаляет $\mathrm{pref}(i) + \mathrm{suf}(y)$ — одно из слагаемых формулы, а меньше оценки удалить нельзя. ∎

    Решение на C++

    G.cpp · 68 строк
    #include <bits/stdc++.h>

using i64 = long long;

struct Info {
    int sum = 0;
    int pre = 0;
    int suf = 0;
    int ans = 0;
};

Info operator+(const Info &a, const Info &b) {
    Info c;
    c.sum = a.sum + b.sum;
    c.pre = std::max(a.pre, a.sum + b.pre);
    c.suf = std::max(b.suf, b.sum + a.suf);
    c.ans = std::max({a.ans + b.sum, a.sum + b.ans, a.pre + b.suf});
    return c;
}

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    
    int n;
    std::cin >> n;
    
    std::string s;
    std::cin >> s;
    
    int sz = 1;
    while (sz < n) {
        sz *= 2;
    }
    std::vector<Info> t(2 * sz);
    for (int i = 0; i < n; i++) {
        if (s[i] == 'T') {
            t[sz + i] = {1, 1, 1, 1};
        } else {
            t[sz + i] = {-1, 0, 0, 0};
        }
    }
    for (int i = sz - 1; i >= 1; i--) {
        t[i] = t[2 * i] + t[2 * i + 1];
    }
    
    int q;
    std::cin >> q;
    
    while (q--) {
        int l, r;
        std::cin >> l >> r;
        l--;
        
        Info L, R;
        for (l += sz, r += sz; l < r; l /= 2, r /= 2) {
            if (l & 1) {
                L = L + t[l++];
            }
            if (r & 1) {
                R = t[--r] + R;
            }
        }
        std::cout << (L + R).ans << "\n";
    }
    
    return 0;
}

    Условие

    $N$ резервуаров сверху вниз, у $i$-го диаметр $D_i$ и вместимость $C_i$. Лишняя вода переливается в ближайший ниже резервуар со строго большим диаметром, а если такого нет — в землю (ответ 0). Запросы независимы: в каком резервуаре остановится вода, если налить $V$ литров в резервуар $R$?

    N ≤ 10⁵Q ≤ 2·10⁵Cᵢ ≤ 1000Dᵢ, Vᵢ ≤ 10⁹

    Ключевая идея

    Для каждого $i$ найдём $nxt_i$ — ближайший ниже со строго большим диаметром (монотонный стек). Связи $nxt$ образуют дерево с корнем 0 («земля»), и вода из $R$ идёт по пути к корню, заполняя вместимости по очереди.

    Подзадачи

    Подзадача 130 б.N ≤ 1000, Q ≤ 2000

    $nxt_i$ ищем перебором вниз. На запрос идём по пути: пока $V > C_v$, вычитаем $C_v$ и переходим в $nxt_v$. Дошли до 0 — ответ 0.

    O(N² + Q·N)
    Подзадача 230 б.Dᵢ < Dᵢ₊₁

    Тогда $nxt_i = i + 1$, и вода идёт по резервуарам подряд. Префиксные суммы вместимостей и бинарный поиск первого $k \ge R$ с $P_k - P_{R-1} \ge V$; если такого нет — 0.

    O((N + Q) log N)
    Подзадача 340 б.без ограничений

    $nxt$ — стеком снизу вверх. Двоичные подъёмы: $up_k(v)$ — вершина на $2^k$ шагов выше, $sum_k(v)$ — суммарная вместимость этих $2^k$ вершин начиная с $v$. На запрос прыгаем на наибольшие $2^k$, у которых $sum < V$, вычитая сумму. У земли вместимость бесконечна.

    Пример: R = 1, V = 25, путь 1 → 2 → 5 с вместимостями 10, 8, 9. Прыжок на 2 шага: 18 < 25, остаётся 7, мы в 5. Там 9 ≥ 7 — ответ 5.
    O((N + Q) log N)

    Почему это верно

    Вода сначала заполняет $R$, излишек по условию попадает в $nxt_R$ (более узкие резервуары между ними она пролетает мимо) и так далее. Так как $nxt_i > i$, циклов нет — это дерево с корнем 0. Вода останавливается в первой вершине пути, где накопленная вместимость $\ge V$; суммы вдоль пути строго растут ($C_i \ge 1$), поэтому её можно найти подъёмами.

    Монотонный стек. Идём снизу вверх. Для $i$ выкидываем из стека всё с диаметром $\le D_i$. Если $j$ выкинули на шаге $i$, то $i$ выше $j$ и $D_i \ge D_j$: для любого резервуара выше $i$ вода сначала встретит $i$, и если ей подходит $j$, то подходит и более близкий $i$. Значит, $j$ больше никогда не станет ответом. Каждый элемент входит и выходит один раз. ∎

using i64 = long long;

constexpr int LOG = 17;
constexpr i64 inf = 1E18;

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    
    int n, q;
    std::cin >> n >> q;
    
    std::vector<int> d(n + 1), c(n + 1);
    for (int i = 1; i <= n; i++) {
        std::cin >> d[i] >> c[i];
    }
    
    std::vector up(LOG, std::vector<int>(n + 1));
    std::vector sum(LOG, std::vector<i64>(n + 1));
    
    std::vector<int> stk;
    for (int i = n; i >= 1; i--) {
        while (!stk.empty() && d[stk.back()] <= d[i]) {
            stk.pop_back();
        }
        up[0][i] = stk.empty() ? 0 : stk.back();
        sum[0][i] = c[i];
        stk.push_back(i);
    }
    sum[0][0] = inf;
    
    for (int k = 1; k < LOG; k++) {
        for (int v = 0; v <= n; v++) {
            up[k][v] = up[k - 1][up[k - 1][v]];
            sum[k][v] = std::min(inf, sum[k - 1][v] + sum[k - 1][up[k - 1][v]]);
        }
    }
    
    while (q--) {
        int r;
        i64 v;
        std::cin >> r >> v;
        
        for (int k = LOG - 1; k >= 0; k--) {
            if (sum[k][r] < v) {
                v -= sum[k][r];
                r = up[k][r];
            }
        }
        std::cout << r << "\n";
    }
    
    return 0;
}

    Условие

    Компания — дерево из $N$ сотрудников с корнем 0, у каждого один из $K$ языков. Выбираем лидера $v$: команда — сотрудники его поддерева с тем же языком. Можно менять местами сотрудника поддерева с другим языком и сотрудника вне поддерева с языком лидера, если они на одном уровне; их подчинённые остаются на местах. Найдите максимальный размер команды $P$ и минимальное число обменов $S$ для него.

    N ≤ 10⁵K ≤ N4 с

    Ключевая идея

    Обмен не выходит за уровень, поэтому уровни независимы. Для лидера $v$ с языком $c$ на уровне $d$: $s_d$ — мест в поддереве, $t_d$ — всего людей с языком $c$, $a_d$ — уже в команде. Тогда

    $$P(v) = \sum_d \min(s_d, t_d), \qquad S(v) = P(v) - \sum_d a_d.$$

    Подзадачи

    Подзадача 112 б.дерево — путь

    На каждом уровне один человек, и он в поддереве лидера ниже него — обменов нет. Лучший лидер — самый верхний человек самого частого языка. Ответ: «частота» и 0.

    O(N)
    Подзадача 219 б.K ≤ 2

    Для каждого языка сливаем снизу вверх словари «уровень → (s, a)» способом small-to-large и поддерживаем сумму минимумов.

    O(N log N)
    Подзадача 327 б.каждый язык ≤ 10 человек

    Для лидера с языком $c$ важны только уровни, где язык $c$ есть, — их не больше 10. $s_d$ считаем бинпоиском по вершинам уровня $d$ в порядке обхода (поддерево — отрезок $[tin_v, tout_v)$), $a_d$ — перебором.

    O(10·N log N)
    Подзадача 423 б.N ≤ 2000

    Для каждого лидера обходим поддерево и считаем $s_d$, $a_d$; $t_d$ для каждого языка и уровня считаем заранее.

    O(N²)
    Подзадача 519 б.без ограничений

    Наблюдение 1. Если у $v$ есть предок $u$ с тем же языком, $u$ не хуже: $s_d(u) \ge s_d(v)$ на каждом уровне, значит $P(u) \ge P(v)$, а при равенстве $\sum a(u) \ge \sum a(v)$ и $S(u) \le S(v)$. Поэтому перебираем только «верхних» лидеров — без предка того же языка. Их поддеревья для одного языка не пересекаются.

    Наблюдение 2. Уровни без языка $c$ дают $t_d = 0$. Для лидера перебираем только уровни своего языка внутри поддерева, как в подзадаче 3: $s_d$ и $a_d$ — бинпоиском.

    Оценка: лёгкий язык ($cnt \le \sqrt N$) — не больше $cnt$ лидеров по $cnt$ уровней, в сумме $\le N\sqrt N$; у тяжёлого языка поддеревья верхних лидеров не пересекаются, работа $\le N$. Итого $O(N\sqrt N \log N)$, на тестах с $N = 10^5$ около 0,15 с. В авторском разборе тяжёлые языки обрабатывают слиянием small-to-large.
    O(N√N log N)

    Почему это верно

    Верхняя граница. На уровне $d$ в команде не больше $s_d$ человек (столько мест) и не больше $t_d$ (столько людей с языком $c$).

    Достижимость. Пока $a_d < \min(s_d, t_d)$, обмен есть: в поддереве есть человек с другим языком ($a_d < s_d$), а снаружи — человек с языком $c$ ($a_d < t_d$). Каждый обмен даёт ровно +1, поэтому на уровне собирается $\min(s_d, t_d)$, и нужно ровно $\min(s_d, t_d) - a_d$ обменов. Лидер в обменах не участвует. ∎

    int D = *std::max_element(dep.begin(), dep.end()) + 1;
    std::vector<std::vector<int>> level(D);
    for (int v : ord) {
        level[dep[v]].push_back(tin[v]);
    }
    
    std::vector<std::vector<int>> cd(k);
    std::vector<std::vector<std::vector<int>>> ct(k);
    {
        std::vector<std::vector<int>> byLang(k);
        for (int v : ord) {
            byLang[lang[v]].push_back(v);
        }
        for (int c = 0; c < k; c++) {
            auto &a = byLang[c];
            std::stable_sort(a.begin(), a.end(), [&](int x, int y) {
                return dep[x] < dep[y];
            });
            for (int v : a) {
                if (cd[c].empty() || cd[c].back() != dep[v]) {
                    cd[c].push_back(dep[v]);
                    ct[c].emplace_back();
                }
                ct[c].back().push_back(tin[v]);
            }
        }
    }
    
    auto count = [&](const std::vector<int> &a, int l, int r) {
        return int(std::lower_bound(a.begin(), a.end(), r) - std::lower_bound(a.begin(), a.end(), l));
    };
    
    int bestP = -1, bestS = 0;
    for (int v = 0; v < n; v++) {
        if (!top[v]) {
            continue;
        }
        int c = lang[v];
        int P = 0, A = 0;
        int j = std::lower_bound(cd[c].begin(), cd[c].end(), dep[v]) - cd[c].begin();
        for (; j < int(cd[c].size()) && cd[c][j] <= maxd[v]; j++) {
            int d = cd[c][j];
            int s = count(level[d], tin[v], tout[v]);
            int t = ct[c][j].size();
            P += std::min(s, t);
            A += count(ct[c][j], tin[v], tout[v]);
        }
        int S = P - A;
        if (P > bestP || (P == bestP && S < bestS)) {
            bestP = P;
            bestS = S;
        }
    }
    
    std::cout << bestP << " " << bestS << "\n";
    
    return 0;
}

    Условие

    В ряду $N$ участников из $T$ команд (номера $0..T-1$, каждая встречается). Нужно пропустить ровно один отрезок $[\ell, r]$ подряд стоящих так, чтобы среди оставшихся каждая команда встречалась не больше одного раза, а пропущенных было как можно меньше. Выведите $\ell$ и $r$ (с нуля); подходит любой оптимальный ответ.

    1 ≤ T < N ≤ 500 0002 с

    Ключевая идея

    Оставшиеся — префикс $[0, \ell)$ и суффикс $(r, N)$. Если $r(\ell)$ — лучший $r$ для данного $\ell$, то $r(\ell)$ не убывает: при росте префикса суффикс может только укоротиться. Поэтому работают два указателя.

    Подзадачи

    Подзадача 18 б.N = T + 1

    Повторяется ровно одна команда — на позициях $p < q$. Пропускаем одного из них: ответ «p p».

    O(N)
    Подзадача 211 б.N = 2T, каждая команда раз в каждой половине

    Останется не больше $T$ человек, значит пропустить нужно $\ge T$. Пропуск первой половины подходит: ответ «0 T−1».

    O(1)
    Подзадача 314 б.N ≤ 500

    Перебираем все пары $(\ell, r)$ и проверяем оставшихся массивом счётчиков.

    O(N³)
    Подзадача 421 б.N = 2T, каждая команда ровно дважды

    Пропустить нужно ровно $T$ подряд, и окно должно содержать хотя бы одного человека каждой команды. Сдвигаем окно длины $T$ и поддерживаем число команд, у которых обе позиции вне окна.

    O(N)
    Подзадача 522 б.N ≤ 5000

    Для каждого $\ell$ с префиксом без повторов идём $r$ от конца влево, добавляя людей в суффикс, пока нет конфликта.

    O(N²)
    Подзадача 624 б.N ≤ 500 000

    Старт: $\ell = 0$, $r$ — позиция перед самым длинным суффиксом без повторов. Добавляя человека $\ell$ в префикс: если его команда уже в префиксе — стоп; иначе сдвигаем $r$ вправо, пока эта команда есть в суффиксе. Каждый раз запоминаем пропуск $[\ell+1, r]$.

    Пример 5 3 1 6 0 5 4 6 2 0: пропуски по ходу — [0,4], [1,5], [2,5], [3,5], [4,7], [5,9]. Лучший — [3,5] длины 3.
    O(N)

    Почему это верно

    Пусть $\ell < \ell'$ и пара $(\ell', r)$ подходит. Оставшиеся при $(\ell, r)$ — подмножество оставшихся при $(\ell', r)$, а в подмножестве набора без повторов повторов нет. Значит, $r(\ell) \le r(\ell')$, и указатель $r$ двигается только вправо. Каждый указатель проходит ряд не больше одного раза. ∎

    Решение на C++

    J.cpp · 46 строк
    #include <bits/stdc++.h>

using i64 = long long;

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    
    int t, n;
    std::cin >> t >> n;
    
    std::vector<int> a(n);
    for (int i = 0; i < n; i++) {
        std::cin >> a[i];
    }
    
    std::vector<int> cnt(t);
    int r = n - 1;
    while (cnt[a[r]] == 0) {
        cnt[a[r]]++;
        r--;
    }
    
    std::vector<bool> pre(t);
    int bl = 0, br = r;
    for (int l = 0; l < n; l++) {
        int x = a[l];
        if (pre[x]) {
            break;
        }
        while (cnt[x] > 0) {
            r++;
            cnt[a[r]]--;
        }
        cnt[x]++;
        pre[x] = true;
        if (r - (l + 1) < br - bl) {
            bl = l + 1;
            br = r;
        }
    }
    
    std::cout << bl << " " << br << "\n";
    
    return 0;
}
